## 1. Scope & Core Principles

The parser service is responsible for transforming untrusted, raw `.eml` byte streams into deterministic, observable, normalized forensic evidence.

### Non-Negotiable Security Guarantees
- **Zero Network Calls**: The parser performs **no** DNS lookups, no WHOIS queries, no external threat intel requests, and never pings or fetches extracted URLs.
- **Zero Code Execution**: Attachments are never executed, unpacked, or opened. HTML is never rendered in a headless browser. JavaScript is never evaluated.
- **Evidence Integrity**: Raw email bytes are preserved unmodified. SHA-256 intake digests are calculated directly against the input byte stream before any parsing or decoding occurs.
- **Observation vs. Inference Separation**: The parser only reports what is **observed** and **normalized**. It does not calculate risk scores, assign threat verdicts, or speculate on attacker motives. Downstream scoring is owned by Person 3, infrastructure intelligence by Person 5, and reporting by Person 6.

## 4. Header & MIME Extraction Logic

### A. Sender & Path Separation
- **`From`**: Normalized into `name` and `address`. RFC 2047 encoded words (`=?UTF-8?B?...?=`) are safely decoded.
- **`Reply-To`**: Extracted strictly if present. If missing, defaults to `None` and raises a `MISSING_REPLY_TO` warning. The parser **never** silently copies `From` into `Reply-To`.
- **`Return-Path`**: Extracted from envelope bounce header. If missing, defaults to `None` and raises a `MISSING_RETURN_PATH` warning.

### B. Received Header Relay Chain
- RFC 5322 Received headers are parsed newest-first from the message, then indexed starting at `1` representing the earliest observable hop in transmission.
- Token bounding guarantees that IP addresses associated with `by` clauses do not bleed into `from_ip`.
- All IP candidates are validated with Python's standard `ipaddress` library.
- If an observed hop IP is classified as private or reserved (RFC 1918 / RFC 5737 documentation ranges), a `PRIVATE_OR_RESERVED_IP_OBSERVED` warning is generated.

### C. Body & URL Extraction
- Plain-text bodies are preserved for downstream NLP / threat detection.
- For HTML-only emails, readable text is safely extracted using standard library `HTMLParser` without browser rendering or script execution.
- URLs are extracted from both plain text and HTML `href` links, parsed using `urllib.parse.urlsplit`, deduplicated, and enriched with `is_https` and `query_present` flags.

### D. Authentication Extraction
- Extracts observed results from `Authentication-Results` and `Received-SPF` headers.
- DMARC `header.from` domain and explicit alignment statuses are parsed when stated; defaults to `aligned: None` if unspecified.
- Raw `DKIM-Signature` headers are preserved verbatim in `raw_authentication_headers`.

## 5. Standard Warnings Dictionary

| Warning Code | Trigger Condition |
| :--- | :--- |
| `MISSING_FROM` | The `From` header is absent. |
| `MISSING_REPLY_TO` | No `Reply-To` header was present. |
| `MISSING_RETURN_PATH` | No `Return-Path` header was present. |
| `MISSING_MESSAGE_ID` | `Message-ID` header is absent. |
| `MISSING_AUTHENTICATION_RESULTS` | Neither `Authentication-Results` nor `Received-SPF` headers exist. |
| `MALFORMED_ADDRESS` | Address does not conform to standard RFC format or lacks `@`. |
| `MALFORMED_DATE` | Date header could not be parsed into a valid timestamp. |
| `MALFORMED_RECEIVED_HEADER` | Received hop could not be parsed or contains corrupt timestamps/IPs. |
| `HEADER_DECODE_WARNING` | RFC 2047 header decoding encountered corrupt byte encodings. |
| `MIME_PARSE_WARNING` | Overall MIME structure parsing failed or message exceeded `max_bytes`. |
| `BODY_DECODE_WARNING` | Body text could not be decoded with specified charset. |
| `URL_PARSE_WARNING` | URL candidate contains invalid syntax or incomplete host. |
| `ATTACHMENT_METADATA_WARNING` | Attachment payload could not be decoded to calculate SHA-256. |
| `PRIVATE_OR_RESERVED_IP_OBSERVED` | Received hop contains an RFC 1918 private or RFC 5737 reserved IP. |
